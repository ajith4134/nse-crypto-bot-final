## Recommendation
No single OSS project ships the full "decision provenance" column set we already have in the 85-col journal; the best move is to **stitch concepts, not adopt a platform**. Agentic Trading Lab is the closest philosophical match — it persists every decision with timestamp, price, portfolio state and free-text reasoning in SQLite, exactly the `decision_snapshot` pattern — and it is Python/FastAPI, so its decision-log schema and review UI ideas port directly. Borrow the human-review vocabulary (per-trade tags, setups, mistakes, playbooks, MFE/MAE, screenshots) from TradeNote and TradeTally as *column/taxonomy inspiration* (their JS stacks make code reuse unattractive), lift structjour's auto-chart-per-trade review flow (Python), and keep QuantStats as the drop-in analytics/tearsheet layer over the journal's equity curve. If a generic provenance store is ever needed beyond the journal DB, Aim's run-tracking model (arbitrary key-value context per record, queryable UI) is the Python-native option for the ML feedback loop.
